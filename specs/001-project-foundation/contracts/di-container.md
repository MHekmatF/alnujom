# Contract: DI Container

**Layer**: `lib/core/di/`
**Constitution**: Principle IV (Clean Architecture Flutter), Principle IX (Future Backend Portability)
**Spec requirement**: FR-008
**Library**: `get_it` + `injectable` (research.md Decision 4)

## Purpose

Provide a single, project-wide service locator that feature modules in later phases use to register their dependencies and resolve cross-cutting services. No feature ever imports another feature's data-layer concrete types — they ask DI for the abstract type and get the bound implementation.

## Public surface

```dart
// lib/core/di/injection.dart

@InjectableInit(
  initializerName: r'$initGetIt',
  preferRelativeImports: true,
  asExtension: false,
)
Future<void> configureDependencies() async {
  await $initGetIt(getIt);
}

final getIt = GetIt.instance;
```

`getIt` is the canonical project locator. `configureDependencies()` is called exactly once, from `main.dart`, before `runApp`.

## Phase 1 registrations

| Type | Lifetime | Implementation | Annotation site |
|---|---|---|---|
| `EnvConfig` | singleton | `EnvConfig` (concrete) | `@singleton` on `EnvConfig` |
| `AppLogger` | singleton | `ConsoleLogger` | `@LazySingleton(as: AppLogger)` on `ConsoleLogger` |
| `PreferencesStore` | singleton | `SecurePreferencesStore` | `@LazySingleton(as: PreferencesStore)` on `SecurePreferencesStore` |
| `SupabaseClientWrapper` | singleton | `SupabaseClientWrapperImpl` | `@LazySingleton(as: SupabaseClientWrapper)` on impl |
| `ThemeCubit` | factory | `ThemeCubit` | `@injectable` on cubit |
| `LocaleCubit` | factory | `LocaleCubit` | `@injectable` on cubit |
| `GoRouter` | singleton | result of `buildAppRouter(logger:)` factory in `app_router.dart` | `@module` provider |

`@LazySingleton` is preferred over `@singleton` for everything except `EnvConfig` so DI graph startup cost is amortized.

## Generated file policy

`lib/core/di/injection.config.dart` is generated by `dart run build_runner build` and **MUST be committed**. PR reviewers diff this file to inspect changes to the DI graph.

`build_runner` is run as part of `flutter pub get` via a melos-style post-fetch hook is NOT used in Phase 1 (overkill); contributors run `dart run build_runner build --delete-conflicting-outputs` manually. CI runs it explicitly (research.md Decision 14, step 5).

## Test rule

Two patterns, depending on the test layer:

**Unit / Cubit tests** — bypass DI entirely. The cubits and the impls are `@injectable`, but their constructors accept all dependencies as parameters. Tests instantiate them directly with Mockito-generated mocks: `ThemeCubit(prefs: mockPrefsStore, logger: mockLogger, initialMode: ThemeMode.system)`. No `getIt` involvement. This matches the `bloc_test` convention.

**Smoke / integration test** — runs the real production DI graph by calling `configureDependencies()` once at test setup. To override the `SupabaseClientWrapper` with a stub (so the test doesn't need a real backend), either:

- set `getIt.allowReassignment = true` at the start of the test and re-register the wrapper with the stub before the first resolution, or
- inject the stub via `--dart-define=SUPABASE_URL='' --dart-define=SUPABASE_ANON_KEY=''` so `EnvConfig.isConfigured` returns `false` and the real wrapper's `initialize()` short-circuits to `FailureResult(ConfigFailure)` (FR-013 path). This is the simpler approach for Phase 1 and is what CI uses.

`GetIt.asNewInstance()` is NOT used; it would require a parallel `configureDependencies()` invocation that targets the new instance, which `@InjectableInit` does not generate. Stick to the two patterns above.

## Phase 1 verification

- `flutter test` exercises `configureDependencies()` once per test isolate without errors.
- `getIt<SupabaseClientWrapper>()` returns the same instance on repeated calls (singleton behavior).
- Removing any of the six registrations above causes a `flutter analyze` error from `injection.config.dart` referencing a missing binding — proves the registrations are wired through codegen.
