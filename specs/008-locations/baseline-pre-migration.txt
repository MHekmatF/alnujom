Section H — Implementation deviation from documented data-model.md § 3.2
--------------------------------------------------------------------------------

The shipped immutability functions enforce_governorate_system_immutability and
enforce_city_system_immutability do NOT carry SECURITY DEFINER, contradicting
the original data-model.md § 3.2 body. Reason: SECURITY DEFINER triggered
Supabase advisor warnings during T018, and Phase 6's actual shipped
enforce_role_system_immutability does NOT use SECURITY DEFINER either. Trigger
functions only read OLD.* and RAISE EXCEPTION — they do not need owner
privileges. The data-model.md spec has been updated in the same Phase 2
session to add a note above the § 3.2 code block explaining the deviation,
and the canonical body shown there now omits SECURITY DEFINER. Live state
verified: pg_proc.prosecdef=false for both functions; proconfig contains
search_path=public,auth.
