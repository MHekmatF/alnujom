- **BLoC state staleness producing duplicate ordering across multi-tap batches** (task #29): Resolved (`87617f6` migration `20260523120001`). ## Accepted As-Is For Phase 11

- **One new advisor WARN: `listing_media_cap_check` mutable `search_path`**: Accepted. Captured in `baseline-pre-migration.txt § I`. The cap-trigger function is a BEFORE INSERT trigger body — never directly callable by authenticated or anon roles, only invoked by the trigger infrastructure on `public.listing_media` writes. The function only accesses `public.listing_media` via its already-schema-qualified `SELECT` query. Risk is low; the function is NOT SECURITY DEFINER. A follow-up polish-time migration could add `SET search_path = public` for clean advisor output — deferred per the Phase 10 R-04 advisor-hardening precedent (which only hardened directly-callable SECURITY DEFINER functions).
- **Pubspec.lock added 25 transitive entries vs R-37's projected ~12**: Accepted. The overage comes from the federated-plugin architecture of `image_picker` (8 platform stubs: `image_picker_{android,ios,linux,macos,windows,web,for_web,platform_interface}` + `cross_file`) and `flutter_image_compress` (6 stubs: `_common`, `_macos`, `_ohos`, `_platform_interface`, `_web`, `flutter_plugin_android_lifecycle`). All are cross-platform stubs that compile only for the target platform — no iOS-only exclusives, no web-only exclusives. R-37 was a conservative pre-implementation estimate; the actual transitive set is normal for Flutter plugins of this scope.
- **Watermark asset is the splash-screen variant of the AlNujom logo**: Accepted for Phase 11. The user-supplied PNG at `assets/images/watermark/logo_watermark.png` (481×440 RGBA) is the splash-screen design (N letter + 10 stars + building accent on a likely-opaque white background). When composited at 15% opacity per R-23, an opaque white background may produce a faded white box behind the logo on publisher photos. The pipeline correctly fails closed if the asset is missing (R-33) but cannot detect "asset present but design wrong". Production-quality alpha-masked variant tracked in Deferred below.
- **60-second timeout enforced at BLoC layer rather than isolate worker** (post-fix `c154bdc`): Accepted per R-39. The BLoC now wraps the entire critical path (file read + `_imageWorker.processImage(...)` + `_uploadImage(...)`) in `.timeout(const Duration(seconds: 60))`; on `TimeoutException` the partial bucket object (if any) is cleaned up by the datasource's existing storage-rollback path. The isolate worker itself is not cancellable mid-job — the timeout cancels the future, the isolate continues processing the orphan, and the next job in the queue starts after. This is simpler than implementing isolate-cancellation and the semantic from the publisher perspective is identical (failed thumbnail → Retry button via re-pick).
- **Storage policy names diverge from bucket-id naming convention**: Accepted. Bucket IDs are hyphenated (`listing-images`, `listing-videos`) but policy names use underscores (`listing_images_*`, `listing_videos_*`) since SQL identifiers cannot contain hyphens without quoting. data-model.md § 6.1 specifies this layout; the divergence is intentional and documented inline in the migration file's leading comment.
