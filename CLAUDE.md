Cross-cutting:
- **Four new dependencies** (departs from Phase 23's zero-new-deps; Phase 22 precedent): `sentry_flutter` + `package_info_plus` (runtime), `flutter_launcher_icons` + `flutter_native_splash` (dev) — all Android-supported, justified per-package in plan § Complexity Tracking; `url_launcher` + `integration_test` already present.
- **No backend change**: no new table / column / RPC / permission key / migration (FR-018). The only "data" is the Supabase-Storage version manifest (public read, operator-written) — not a DB object.
- **Security at the edges** (Principle III): crash payloads scrubbed of synthetic-email/phone + Vault + decrypted PII + tokens (`beforeSend`); release keystore + DSN never committed (gitignored / dart-define) + signing **fails closed**; the **APK secret-scan** confirms nothing leaked into the shipped binary.
- **Fail-open / non-blocking**: an unreachable Sentry endpoint never blocks `runApp`; an unreachable/malformed version manifest is a silent no-op — neither bricks the app (mirrors the Phase 23 fail-open + Phase 22 degraded-mode postures).
- **QA evidence is hybrid** and the standing "no new automated tests until MVP feature-complete" convention is relaxed for **exactly one** test (the primary-publish `integration_test`); maintenance (two-device) + push stay manual; AVD walks count as primary QA evidence; the §15 <3 s cold-start budget is **advisory, recorded in release notes, not a gate**.
