Cross-cutting:
- [docs/decisions/0001-secrets-and-pii-storage.md](docs/decisions/0001-secrets-and-pii-storage.md) — `agency_verification_requests`' identity material (the ID-document number + commercial-registration number) is Vault-stored (admin-decrypt-only via `app_vault_secret_for_agency`, gated on `agencies.view`), NEVER a plaintext column and NEVER in any view; verification document FILES live in the private `agency-documents` storage bucket (owner/admin only). RLS on all three new tables; `v_agencies` is SECURITY DEFINER with an explicit owner/member/admin WHERE; agency moderation is gated at BOTH the `moderate_agency` Edge Function (per-action `agencies.approve`/`agencies.suspend`) AND the service-role-only `moderate_agency_internal` RPC (Principle III "checks at both ends").
- ZERO new pubspec packages in Phase 19 (FR-037 / R-135) — agencies use the inherited Flutter/BLoC/`go_router`/`supabase_flutter` stack + in-house Postgres tables + Vault + Storage + one Deno Edge Function reusing the Phase 12 runtime. No Android manifest change. No new Postgres extension. ZERO change to `lead_events` and the `listings.status` enum (FR-040).
- Write-path posture: `create_agency` (binds `owner_user_id := auth.uid()`), the member RPCs (`invite`/`respond`/`set_role`/`remove`, each self-gating on `is_agency_admin` or the invitee's `auth.uid()`), and `submit_agency_verification` are the ONLY creation/membership/verification paths; `moderate_agency_internal` (service-role) is the ONLY status-transition path; the three tables grant NO client INSERT/UPDATE/DELETE. One agency per owner (UNIQUE `owner_user_id`); one OPEN verification request per agency (`ux_agency_open_verification`).
- Soft publish gate (Q1=A / R-143): publishing reuses the existing per-user `publisher_status='approved'` RLS UNCHANGED; the only new logic is the `submit_listing` amendment validating the publisher is an `active` member of the listing's agency (status ∈ {pending,approved}). Agency `approved` status gates ONLY the public profile + the verified badge (`v_agencies` + the `v_listings_public` badge join are approved-only). Suspension hides the profile/badge + blocks new agency publishing but does NOT mass-mutate the agency's listings (R-149).
- Member-management authorization is the per-agency `agency_members.member_role='admin'` row (the `is_agency_admin(agency_id)` SECURITY DEFINER predicate), NOT a hardcoded role branch and NOT the global `agency_admin` role (R-140 / FR-038); the admin verification surface is gated by `agencies.view`/`agencies.approve`/`agencies.suspend` (Principle VII).
- Forward-stated future work: reporting of agencies, a promoted/paid agency tier, ownership transfer between users, multiple agencies per owner, push notification of agency invites (Phase 22), and a shared cross-member agency inquiries inbox are each a separate future spec — OUT of Phase 19 scope.
