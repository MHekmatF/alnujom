Cross-cutting:
- [docs/decisions/0001-secrets-and-pii-storage.md](docs/decisions/0001-secrets-and-pii-storage.md) — Reports + moderation are sensitive moderation data: RLS on `public.reports` is reporter-self OR `reports.manage` (no publisher path, no aggregate count — FR-028); `public.moderation_actions` is `reports.manage`-read-only and append-only; `v_reports` is SECURITY INVOKER inheriting the base RLS; neither table has an `anon` policy. Resolution is gated at BOTH the `resolve_report` Edge Function (`reports.manage`) AND the service-role-only `resolve_report_internal` RPC (Principle III "checks at both ends").
- ZERO new pubspec packages in Phase 18 (FR-031 / R-119) — reports/moderation use the inherited Flutter/BLoC/`go_router`/`supabase_flutter` stack + in-house Postgres tables + one Deno Edge Function reusing the Phase 12 runtime. No Android manifest change. No new Postgres extension. ZERO change to `lead_events.event_type` and the `listings.status` enum (Q1=A).
- Write-path posture: `submit_report` SECURITY DEFINER RPC (authenticated-only) is the ONLY report-creation path (no client INSERT grant — `reporter_user_id` un-forgeable); resolution + the `start_report_review` soft-claim are the ONLY report-mutation paths (no client UPDATE/DELETE); `moderation_actions` is written ONLY by `resolve_report_internal`. The open-report dedup ("one open report per reporter+listing", FR-004) is a partial unique index + RPC guard; a terminal report does not block a fresh re-report.
- Moderation actions reuse the existing listings status enum (Q1=A): dismiss=no change, hide→paused, mark_duplicate→rejected (reason "duplicate"), delete→deleted — flowing through the Phase 12 status-transition + `listing_status_history` + audit machinery; a listing-affecting action auto-resolves sibling open reports in the same transaction (Q5=A), while `dismiss` affects only its own report.
- Reporter visibility (Q3=Both): a "My Reports" page (Profile tile → `/reports`) + a reporter-only inline status banner on the Phase 13 listing details page, both reading `v_reports` and self-scoped by RLS.
- Forward-stated future work: publisher notification of reports against their listings is Phase 22 (push/Realtime), NOT Phase 18; reporter reputation scoring, report rate-limiting beyond the open-report dedup, report-reason-specific automation, automatic duplicate detection (IMPLEMENTATION_PLAN §1 non-goal), and reporting of non-listing targets (users/agencies/inquiries) are each a separate future spec.
