- The `app.map_jitter_salt` Postgres GUC MUST be set out-of-band on the live Supabase project via `ALTER DATABASE postgres SET app.map_jitter_salt = '<256-bit-hex>';` BEFORE the Phase 15 view + RPC are queryable. Setup procedure documented in `quickstart.md` §2 and `supabase/docs/map_jitter_coordinates.md`. Rotation re-jitters every approximate listing's marker (acceptable per FR-003).
- The marker dataset cache is session-scoped per R-89 + FR-014a — `MapBloc` holds the markers in `MapLoaded` state, the user triggers re-fetch via the explicit `MapRefreshButton` (pull-to-refresh rejected due to map-pan gesture conflict). No auto-refresh on timer or on app foreground-resume, matching Phase 13 Q6=A's home-feed freshness model.
- Geolocation usage is scoped to client-side pan/zoom only per FR-015c — the device's position is NEVER persisted server-side, NEVER logged to audit trails, NEVER used to filter the marker dataset. A grep gate in `quickstart.md` §8f verifies no Supabase call carries the user's coordinates.
- Forward-stated Phase 16 contract: Phase 16 wires the Call / WhatsApp / inquiry CTAs from `ListingDetailsPage`. Phase 16 MUST cite the Q3=A forward-state convention from Phase 13. Phase 15 does NOT introduce any contact wiring on the map surface; marker preview popover taps land on Phase 13's `/listings/:id` which Phase 16 will populate.
- Forward-stated Phase 22 contract: Phase 22 adds Realtime subscription + push-notification deep-links. Phase 15's `/map` route is a deep-link target (the back-button convention from R-96 handles cold-launch entry). When Realtime ships, `MapBloc` may subscribe to `public.listings` changes filtered to `status='approved'` to auto-update the marker dataset without manual refresh.
- Forward-stated PostGIS adoption: A future spec MAY enable PostGIS when the catalog scales past ~10k approved listings or when viewport-bound dataset filtering becomes necessary per FR-001a's forward statement. Until then, plain `numeric(9,6)` columns + client-side clustering suffice.
- Forward-stated dark-mode tile source: A future spec MAY add a dedicated dark-mode OSM tile source (e.g., a CartoDB Dark Matter mirror) for the map page's dark theme. Phase 15 ships one tile source for both themes; the marker + popover chrome respects the active theme tokens.
- Forward-stated last-viewed-region persistence: A future spec MAY persist the user's last map zoom + pan across sessions (similar to how Aqarmap / Bayut remember the last-viewed city). Phase 15 always opens to Syria-wide overview per Q3=A.
