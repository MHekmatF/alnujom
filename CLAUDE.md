Cross-cutting:
- [docs/decisions/0001-secrets-and-pii-storage.md](docs/decisions/0001-secrets-and-pii-storage.md) — Favorites are private behavioral data: RLS on `public.favorites` is strictly self-only (`user_id = auth.uid()`), the `v_favorites` view is SECURITY INVOKER (inherits that RLS) and projects ZERO publisher private fields, and there is NO `favorites.view_all` permission — no publisher, admin, or anonymous reader path, and no aggregate save-count exposed anywhere (FR-017..FR-019). This is a stricter posture than Phase 16's three-tier inquiries visibility (favorites have no legitimate cross-user reader).
- ZERO new pubspec packages in Phase 17 (FR-030 / R-109) — favorites use the inherited Flutter/BLoC/`go_router`/`supabase_flutter` stack. No Android manifest change. No new Postgres extension.
- Write-path posture: `add_favorite(uuid)` SECURITY DEFINER RPC is the ONLY favorite-creation path (no client INSERT grant on `public.favorites`), guaranteeing the deduped `favorite_added` event cannot be bypassed; un-favorite is a direct self-only DELETE (Q5=A). The `favorite_added` event fires once per `(user_id, listing_id)` ever, deduped via an `EXISTS` guard against the Phase 16 `lead_events` history (Q3=B); un-favorite emits no event (there is no `favorite_removed` type).
- The live home/search/map feeds render BESPOKE card widgets (`HomeListingCardTile`, `SearchResultCard`, `MarkerPreviewPopover`), NOT the Phase 2 `PropertyCard` — whose `favorite`/`onFavoritePressed` heart slot is used only in `lib/debug/theme_gallery_page.dart`. Phase 17 introduces a shared `FavoriteHeartButton` each bespoke surface embeds (R-118); it does NOT route favorites through `PropertyCard`.
- The FavoritesPage shows favorites whose listing has left `approved` (sold/rented/rejected/paused/expired/deleted) with a "no longer available" indicator and keeps them tappable → Phase 13 details (Q4=A); the `v_favorites.is_available` flag (computed, not status-filtered) drives this.
- Forward-stated Phase 19/20 contract: the `favorite_added` lead events Phase 17 begins writing feed the future agency-analytics (Phase 19) and admin-dashboard (Phase 20) surfaces; Phase 17 ships the data, no favorites-analytics dashboard.
- Forward-stated future specs: saved searches, collections/folders/tags for favorites, popularity/save-count display, and price-drop notifications are explicitly out of scope for Phase 17 (each a separate spec with its own privacy review).
