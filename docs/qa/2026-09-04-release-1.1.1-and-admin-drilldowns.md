# The 1.1.1+3 build, and the three admin pages nobody had opened — 2026-09-04

Two things in one session, both on the **Infinix X692** (Android 10, arm64-v8a)
over USB, signed in as super-admin.

1. Plan item **A3** — cut the release that goes on Telegram, and look at the
   launcher icon and splash on hardware for the first time.
2. The last line of plan item **A2** — three admin pages reachable only by path
   interpolation, so nobody had confirmed they open.

---

## A3 — the build

`1.1.1+3`, `--split-per-abi --obfuscate --split-debug-info`, signed with the
release key (`apksigner`: `CN=Hekmat Fanari, OU=AlNujom`, v2 scheme). Installed
over `1.1.0+2` with `install -r`: the signed-in session survived, cold start
**1.98 s** to first frame, Home rendered with the publish FAB.

Hashes, sizes and the full verification table are in
[`docs/release/v1.0.0.md`](../release/v1.0.0.md). The two defects the icon check
found — and what replaced the assets — are written up there too, because that is
where someone building the next release will look.

The short version: the adaptive icon's foreground was not transparent. Its alpha
was a hard bucket outline left by an automatic background removal, so every
launcher drew a notched rectangle of pale sky behind the emblem, with a strip of
chopped-up wordmark along the bottom. The splash had the same slab. Both are now
derived by `tool/build_orbit_icon_assets.py`, and moving the source art out of
`assets/branding/` — a declared asset directory ships everything in it — took the
arm64 download from 37.8 MB to **31.7 MB**.

### Three things seen while building that are not defects

- **The pre-Android-12 native splash is plain navy**, and always has been. The
  generated `drawable/background.png` is a 1×1 solid colour, so `background_image`
  never reached that path however the pubspec set it. Left alone — the app draws
  its own splash the moment Flutter starts, and a flat navy hand-off is quieter
  than a second piece of artwork appearing for a fraction of a second. The
  pubspec comment claimed otherwise and has been corrected.
- **The app briefly shows the sign-in screen on every cold start**, then
  cross-fades to the signed-in Home. Caught in a screenshot on a good
  connection, so it is not the offline behaviour recorded on 2026-09-03 — it is
  the auth bootstrap order, visible for well under a second. Same root cause,
  same fix, still not a one-liner.
- Gradle warns that its own version, AGP and Kotlin will soon drop below
  Flutter's floor. True; A13, not a release blocker.

### One thing that needs a decision, not a fix

**The app shows two different logos three seconds apart.** The native splash is
the navy "orbit" emblem with a Latin `ALNUJOM REAL ESTATE` wordmark. The moment
Flutter starts, `splash_page.dart` draws a **white** screen with the blue
N-in-a-ring-of-stars mark and the Arabic النجوم wordmark.

The second one is plainly the real identity: it is Arabic, and it matches
`logo_mark.png` and `logo_full.png`, which the app bar and the auth screens
already use. The orbit emblem reads like artwork that was promoted to the icon
in Phase 033 and never reconciled with the rest. Nothing was changed — picking
one is the owner's call — but it is the first three seconds of every launch, and
a white flash after a navy splash is the most visible part of it.

## A2 — the three drill-in pages

All three open, with real data, and none of them is a stub.

| Page | Reached by | Result |
|---|---|---|
| Currency rate history | Currencies → menu → **عرض السجل** | Opens. Real history for SYP←USD: four derived rates with values, effective timestamps in Arabic, and the source row each was derived from. A chart view sits behind a second app-bar action. |
| Governorate → city → area | Locations → **حلب** → **حلب** | Both levels open. حلب lists its 9 cities with area counts (14 / 4 / 8 / 5 / 3 / 8 / 7 …), and the city lists its areas (وسط جبل سمعان, أتارب, دارة عزة, الحاضر, حريتان …). A hidden city renders as `مخفي` with 0 areas rather than disappearing. |
| Role editor | Super-admin → **الإدارة الفائقة** → a role | Opens on **مشرف / Moderator** with its Arabic and English names, description, and the permission catalogue grouped by section. |

**The role editor loads the role's current permissions, and this was worth
checking.** The first screenful is all unchecked, which looks alarming on a role
the list page says has 5 permissions — a role editor that opened blank would let
an admin save and silently wipe a role. It does not: scrolling down finds
`users.view` ticked. Confirmed in the accessibility tree as well as on screen
(one `checked="true"` among nine checkboxes on that screenful).

### One real gap found here

**The permission catalogue is English only.** On an Arabic-first admin screen it
reads `Admin ads and banners.`, `Approve agency applications.`, `Suspend an
approved user.`, `Mutate app-wide settings.` — with the trailing full stop
reordered to the front of the line by RTL, the same bidi behaviour that made the
exchange rate read backwards.

`lint_l10n_literals` cannot see this: the strings are not in the code. They are
the `description` column of the `permissions` table, rendered as they come out of
the database. Fixing it means either Arabic descriptions in the table (a
migration, and the linters stay blind to the next one) or dropping the sentence
and keeping the key, which is already shown beneath each line in monospace and
is the part an admin actually navigates by.

Not fixed here: it is a schema change on a screen only the owner and future
moderators see, and it is worth deciding which of the two shapes is wanted before
writing a migration.
