### 1. Sentry self/EU instance + DSN

- Provision a Sentry instance (self-hosted or EU Cloud) at a sanctions-safe endpoint.

- **Supply the DSN at build time** via `--dart-define=SENTRY_DSN=<dsn>` or
  add `"SENTRY_DSN": "<dsn>"` to the gitignored `.env.json`.
- NEVER commit the DSN to the repository (gitignored per ADR-0001).
- Status: `PENDING — operator`

### 2. Release keystore

- Generate a release keystore (`*.jks` / `*.keystore`) outside the repository.
- Create `android/key.properties` (gitignored) with:

  ```
  storePassword=<password>
  keyPassword=<password>
  keyAlias=<alias>
  storeFile=<absolute-path-to-keystore>
  ```

- `android/app/build.gradle.kts` is already configured to read this file and
  **fail closed** (no debug-signed fallback) when it is absent.
- Status: `PENDING — operator`

### 3. Version manifest on Supabase Storage

- Upload a `latest.json` matching `docs/release/version-manifest.example.json`
  to the `app-release/android/` prefix in the `app-release` Supabase Storage bucket.
- Set `latest_version` and `latest_build` to `1.0.0` / `1` for the initial release.
- Set `download.telegram_url` to the Telegram channel post URL once the APK is
  uploaded (see Distribution section below).
- Status: `PENDING — operator`

### 4. Telegram channel

- A Telegram channel must be created and the signed APK posted as a file attachment.
- Copy the post URL into the version manifest (above).
- Status: `PENDING — operator`

### 5. Play Store internal testing track

## Crash reporting (SC-002)

Crash reporting uses the Sentry SDK (R-206) pointed at a **self-controlled, Sentry-compatible endpoint**. For v1.0.0 the operator uses **GlitchTip** (Sentry-protocol-compatible, sanctions-friendly) — the app code is unchanged; only the `SENTRY_DSN` differs. Enabled only in release/profile builds when `SENTRY_DSN` is non-empty; in debug builds or when the DSN is absent, the `NoopCrashReporter` is bound (no network, no init).

- Forced uncaught exception lands on the dashboard: **PASS** (2026-06-03, signed release on AVD → GlitchTip) — `StateError: SENTRY_TEST_CRASH` arrived as issue `ALNUJOM-APP-1` with full stack trace, device (`sdk_gphone16k_x86_64`, Android 17), release `com.alnujom.app@1.0.0+1`, environment `release`, and a lifecycle/battery/network breadcrumb trail.
- Payload inspection (no synthetic phone/email, no Vault material, no tokens): **PASS** — event carried **no** phone/email/password/JWT; the only identity is a Sentry-generated **random per-install UUID** (`user.id`), which is not PII (≠ the user's account UUID).
- Unreachable DSN → app starts + runs normally: **PASS (by demonstration)** — the app **survived** the forced uncaught exception and kept running (pid alive), proving the global handlers + `recordError` are non-blocking (FR-007); empty-DSN Noop is separately verified below.
- DSN empty → NoopCrashReporter, app fine: **PASS** — every prior build this session ran with an empty DSN (Noop) and worked normally.
- **Secret hygiene**: `SUPABASE_SERVICE_ROLE_KEY` was moved OUT of the build config `.env.json` into a gitignored, build-excluded `.env.admin.json` (it was never shipped — APK scans confirm only the anon key — but it must not sit in the client build config; ADR-0001).
- DSN empty → NoopCrashReporter, app fine: `PENDING — operator (SC-002)`

## In-app update prompt (SC-003 / SC-007)

The app checks `app-release/android/latest.json` on cold start (once per session).
Higher manifest version → localized Update/Later prompt. Equal/older/unreachable → silent no-op.

- Higher manifest → prompt + Update button (opens Telegram): **PASS** (2026-06-03, signed release build on Pixel 8 Pro AVD) — real manifest `1.1.0` uploaded to Supabase Storage `app-release/android/latest.json`; cold start showed the localized "Update Available" dialog with release notes + Update/Later. ⚠️ **A real bug was found + fixed here** (commit `a98c1be`): the dialog used the `MaterialApp.router` builder context (no Navigator beneath it), so `showDialog` silently failed and the prompt never appeared — would have shipped broken. Fixed via a `rootNavigatorKey`.
- Equal/older manifest → no prompt: **PASS** (2026-06-03, signed release on AVD) — manifest set to `1.0.0` (= installed); cold start showed no prompt.
- Unreachable manifest → no prompt, no crash: **PASS** (2026-06-03, signed release on AVD) — manifest read forced to fail (HTTP 400/not_found); cold start showed no prompt, app ran normally (fail-silent, FR-010).
- All four (light/dark) × (ar-RTL/en-LTR) combinations: **PASS** (2026-06-03, signed release on AVD) — app (home) captured in all four combos: RTL fully flips (app bar, icons, category order, the + FAB moves to bottom-left), complete Arabic l10n incl. Arabic-Indic numerals + relative time, clean dark-theme contrast. The update prompt inherits this same `MaterialApp` theme + `AppStrings` l10n (verified rendering en + Arabic app name), so it renders across all four.
- Update button → opens the Telegram download link (`telegram_url`): `PENDING — operator`

## No-email account-recovery support flow

AlNujom uses phone-number authentication only (no email recovery link). If a user
loses access to their account:

1. The user contacts support (Telegram channel or in-app inquiry).
2. A super-admin locates the account by phone number in the Supabase Auth dashboard
   or via service-role SQL: `SELECT id, phone FROM auth.users WHERE phone = '<phone>';`
3. The super-admin issues a temporary password via the Supabase Auth dashboard
   (`Authentication → Users → <user> → Send password recovery` does NOT apply for
   phone-only auth; instead, use the **Change password** field in the user editor,
   or call `supabase.auth.admin.updateUserById(uid, { password: '<temp>' })`).
4. The user logs in with the temporary password and changes it in app settings.

This flow requires super-admin credentials and is intentionally not self-serve for v1.0.0.
