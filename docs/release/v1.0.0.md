## Operator prerequisites (gate the release — must be provisioned first)

The following items are NOT code — they must be provisioned by the operator
before a production build can be created or distributed.

### 1. Sentry self/EU instance + DSN

- Provision a Sentry instance (self-hosted or EU Cloud) at a sanctions-safe endpoint.
- Create an AlNujom project; copy the DSN.
- **Supply the DSN at build time** via `--dart-define=SENTRY_DSN=<dsn>` or
  add `"SENTRY_DSN": "<dsn>"` to the gitignored `.env.json`.
- NEVER commit the DSN to the repository (gitignored per ADR-0001).
- Status: `PENDING — operator`

### 2. Release keystore

- Generate a release keystore (`*.jks` / `*.keystore`) outside the repository.
- Create `android/key.properties` (gitignored) with:

  ```
  storePassword=<password>
  keyPassword=<password>
  keyAlias=<alias>
  storeFile=<absolute-path-to-keystore>
  ```

- `android/app/build.gradle.kts` is already configured to read this file and
  **fail closed** (no debug-signed fallback) when it is absent.
- Status: `PENDING — operator`

### 3. Version manifest on Supabase Storage

- Upload a `latest.json` matching `docs/release/version-manifest.example.json`
  to the `app-release/android/` prefix in the `app-release` Supabase Storage bucket.
- Set `latest_version` and `latest_build` to `1.0.0` / `1` for the initial release.
- Set `download.telegram_url` to the Telegram channel post URL once the APK is
  uploaded (see Distribution section below).
- Status: `PENDING — operator`

### 4. Telegram channel

- A Telegram channel must be created and the signed APK posted as a file attachment.
- Copy the post URL into the version manifest (above).
- Status: `PENDING — operator`

### 5. Play Store internal testing track

- Configure the Play Store internal testing track and enroll QA testers.
- Upload the signed release APK / AAB.
- This is a QA-only track for v1.0.0; public rollout is a separate decision.

## No-email account-recovery support flow

AlNujom uses phone-number authentication only (no email recovery link). If a user
loses access to their account:

1. The user contacts support (Telegram channel or in-app inquiry).
2. A super-admin locates the account by phone number in the Supabase Auth dashboard
   or via service-role SQL: `SELECT id, phone FROM auth.users WHERE phone = '<phone>';`
3. The super-admin issues a temporary password via the Supabase Auth dashboard
   (`Authentication → Users → <user> → Send password recovery` does NOT apply for
   phone-only auth; instead, use the **Change password** field in the user editor,
   or call `supabase.auth.admin.updateUserById(uid, { password: '<temp>' })`).
4. The user logs in with the temporary password and changes it in app settings.

This flow requires super-admin credentials and is intentionally not self-serve for v1.0.0.
